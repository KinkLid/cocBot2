# Журнал переписки с Telegram-ботом

Функция выключена по умолчанию, потому что журнал содержит персональные данные и текст сообщений.

## Включение

В runtime `.env`:

```dotenv
CONVERSATION_LOG_ENABLED=true
CONVERSATION_LOG_DIR=./logs/conversations
CONVERSATION_LOG_MAX_BYTES=5000000
CONVERSATION_LOG_BACKUPS=3
```

После изменения `.env` требуется перезапуск `cocbot`.

## Формат хранения

Для личных чатов создаётся отдельный JSONL-файл:

```text
logs/conversations/user_<telegram_id>.jsonl
```

Для групповых чатов, где исходящее сообщение нельзя однозначно отнести к одному участнику:

```text
logs/conversations/chat_<chat_id>.jsonl
```

Каждая строка — отдельная JSON-запись с направлением `incoming` или `outgoing`, временем записи, идентификаторами чата/пользователя/сообщения, типом содержимого и текстом. Запись выполняется только на сервере; в Git эти файлы не попадают.

## Что записывается

- входящие текстовые сообщения и подписи к вложениям;
- нажатия inline-кнопок (`callback_data`);
- исходящие сообщения, редактирования и удаления;
- метаданные вложений: тип, размер, имя файла, MIME-тип и `file_unique_id`;
- контакт или координаты, если пользователь сам отправил их боту.

Бинарное содержимое фотографий, документов, аудио и видео не скачивается и не копируется в журнал.

## Защита секретов

Сообщение, введённое в состоянии `waiting_for_player_token`, всегда записывается как:

```text
[REDACTED: player token]
```

Реальный Clash of Clans player token в журнал не попадает.

## Ротация и права

- основной файл ограничен `CONVERSATION_LOG_MAX_BYTES`;
- старые версии хранятся как `.1`, `.2` и так далее;
- число резервных версий задаёт `CONVERSATION_LOG_BACKUPS`;
- каталог создаётся с правами `0700`, файлы и lock-файлы — `0600`;
- ошибка записи журнала логируется, но не должна останавливать обработку сообщений ботом.

Доступ к каталогу должен оставаться только у сервисного пользователя и root. До включения функции необходимо определить срок хранения и порядок удаления персональных данных.
